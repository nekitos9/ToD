# Project instructions

Проект — статическое веб-приложение "Правда или действие".

## Источники требований

1. `docs/Описание приложения.docx` — главный источник бизнес-логики и поведения приложения.
2. `docs/Паки и вопросы.xlsx` — источник данных карточек, паков и связанных параметров.
3. `docs/FIGMA.md` — ссылка и пояснения к Figma.
4. Figma — источник визуального дизайна, layout и UI-состояний.

Если источники противоречат друг другу:
- логика из документа имеет приоритет;
- визуальный дизайн берётся из Figma;
- существенные неоднозначности нельзя додумывать — нужно спросить пользователя.

## Технические ограничения

- Приложение должно публиковаться через GitHub Pages.
- Никакого обязательного backend.
- Никакого PHP или серверного runtime.
- Интерфейс должен работать на смартфонах, планшетах, ПК и ТВ.
- Для ТВ должна поддерживаться навигация фокусом с пульта/клавиатуры.
- После первой загрузки приложение желательно должно работать офлайн.
- Незаконченная игра должна сохраняться локально.
- Не добавлять внешние сервисы, аккаунты пользователей или серверную БД без отдельного согласования.

## Работа с проектом

Перед существенными изменениями сначала изучить документацию.

Если решение влияет на игровую механику или UX и явно не описано в источниках — спросить пользователя.

Перед завершением задачи:
- проверить TypeScript;
- запустить тесты;
- выполнить production build;
- сообщить о найденных проблемах.

## Данные карточек

- `docs/Паки и вопросы.xlsx` является единственным источником данных карточек и паков.
- Не редактировать сгенерированные данные вручную.
- При production build автоматически:
  1. читать XLSX;
  2. валидировать данные;
  3. преобразовывать их в нормализованный формат, используемый приложением.
- При ошибке данных сборка должна завершаться с понятным сообщением, по возможности с номером строки и причиной.
- Проверять как минимум:
  - уникальность `id`;
  - допустимые значения типа карточки;
  - существующие паки;
  - существующие грани;
  - корректность поля `Отношения`;
  - корректность числа `Другие игроки`;
  - соответствие `*PLAYER*`, `*PLAYER2*`, `*PLAYER3*` значению `Другие игроки`;
  - отсутствие пустого текста карточки.
- Сгенерированный JSON/TS-файл не должен быть источником истины.
